# Фундамент сохранений

Существующий `SaveManager` остаётся точкой доступа. Zenject предоставляет один экземпляр из ProjectContext. Нового хранилища вне существующей папки Saves и второго менеджера игрового состояния нет.

## Расположение и формат

- `Application.persistentDataPath/Saves/*.json` — существующие чертежи `SaveShip`, в прежнем плоском формате; дополнительные `formatVersion` и `checksum` игнорируются старыми JSON-загрузчиками.
- `Saves/Profile/player.json` — профиль с разделами `settings`, `onboarding`, `progression`, `runState`. Каталог профиля не попадает в список кораблей.
- `*.bak` — последняя проверенная версия; `*.tmp` — подготовленная запись. Повреждённый основной файл при восстановлении сохраняется как `*.corrupt-<id>`.

Версия протокола сейчас **1**. Старый JSON без версии считается версией 0. SHA-256 проверяет случайное повреждение содержимого; это не шифрование и не защита от намеренного редактирования. DTO по-прежнему сериализуются Unity JsonUtility. Уже установленный Newtonsoft используется для строгой проверки структуры JSON, версии, целостности и объединения изменённых полей; новых зависимостей не добавлено.

## Разделы

| Раздел | Содержимое |
| --- | --- |
| Settings | Код языка, громкость/выключение музыки и эффектов, qualityLevel, targetFrameRate. Значение -1 сохраняет проектные значения графики/FPS при будущем подключении. |
| Onboarding | Явный hasLaunched, TutorialStatus: NotStarted / InProgress / Completed / Skipped, версия обучения, текущий шаг и список завершённых шагов. |
| Progression | Существующие ресурсы, завершённые уровни/сложности, владение контентом и улучшения. Чертежи оборудования доступны через прежний SavedShips, без дублирования в профиле. |
| RunState | Только контракт расширения: hasActiveRun, modeId, stateVersion, payloadJson. Текущие режимы не возобновляются автоматически. |

Настройки пока **не применяются** к существующему Audio/UI/Localization. PlayerPrefs текущих экранов, управления и выбранных кораблей остаются прежними. Их перенос/подключение — следующий этап, с отдельной миграцией. Обучение и игровая логика прогрессии не добавлены.

## API

```csharp
[Inject] private SaveManager saves;

bool firstLaunchThisSession = saves.IsFirstLaunch;
SettingsSaveData settings = saves.ReadSettings(); // отдельный снимок

saves.UpdateSettings(data => data.languageCode = "ru"); // отложенно
saves.SetTutorialState(TutorialStatus.InProgress, "movement"); // сразу
saves.UpdateOnboarding(data => data.completedStepIds.Add("movement"));
saves.Flush(); // явная важная контрольная точка
```

Есть аналогичные Read/Update для Progression и RunState и полный ReadSnapshot. Снимки и ссылки, сохранённые из callback, отсоединены от внутреннего состояния. Изменять данные следует через Update, а не через возвращённый снимок. Параметр `saveImmediately` включает немедленную запись; одинаковые значения не вызывают лишней записи. API следует вызывать из главного потока Unity.

`IsFirstLaunch` фиксируется на сессию из `hasLaunched`; первый запуск сохраняет этот флаг. Старые данные подтверждают предыдущий запуск, но **не подтверждают завершение обучения**: после импорта его состояние остаётся NotStarted. Существование файла не используется как признак прохождения обучения.

`SaveLifecycleHost` добавляется во время выполнения на существующий объект ProjectContext. Он сбрасывает dirty-данные не чаще раза в секунду и при pause=true, focus=false, quit, уничтожении контекста. При чистом профиле записи нет. Важные списания ресурсов, завершение уровня, покупки/улучшения и состояния обучения сохраняются сразу. Списание за контент и изменение владения попадают в один JSON-коммит. Ресурсы, добавляемые часто, объединяются до следующего checkpoint/автосохранения. Внезапное принудительное завершение процесса до checkpoint может потерять последнюю секунду отложенных изменений.

## Надёжность и миграция

Сначала записывается полный UTF-8 JSON во временный файл с Flush(true), затем заменяется основной. Используется File.Replace; при отсутствии этой операции — защищённая временным файлом и резервной копией замена. Кратковременная блокировка замены допускает две повторные попытки по 10 мс; при постоянной ошибке основной файл не удаляется и dirty-состояние сохраняется для следующей попытки. При неподдерживаемом File.Replace возможен промежуток без основного файла: следующий запуск восстанавливает его из проверенного temp/backup.

Чтение проверяет основной файл, затем temp, backup и backup temp. Более новый неизвестный формат не заменяется старой копией. При отсутствии исправных кандидатов возвращаются безопасные значения в памяти, выставляются `IsReadOnly` и `LastError`; повреждённые данные не перезаписываются значениями по умолчанию. UI сможет реагировать на `SaveFailed`. Сначала устраните причину/восстановите файл, затем перезапустите профиль/приложение; автоматического сброса прогресса нет.

При первом чтении профиля импортируются прежние `player_resources.json`, `level_progress.json`, `content_progress.json` из persistentDataPath. Все исходные файлы остаются на месте неизменёнными. После создания профиля они больше не являются источниками чтения/записи; явный сброс раздела не приводит к повторному импорту старых значений. Ключ cores и значение старых завершений Normal сохранены.

Общие операции записи синхронизированы. Для совместимости с прежними конструкторами без DI коммит объединяет изменённые поля с последней сохранённой версией: изменение уровней не откатывает ресурсы другого экземпляра. Конфликт изменения одного и того же поля разрешается последним коммитом. В игровом коде используйте общий экземпляр Zenject.

Будущие миграции добавляются последовательно в `PlayerSaveMigration.Read`; при изменении формата нужно увеличить версию JsonSaveFile и протестировать старые фикстуры. Версию нельзя повышать без соответствующей миграции. Новые языки/обучение/режимы подключаются через существующие Read/Update API.

## Проверки

`AgentScripts/VerifySaveFoundation.cs` проверяет сохранения в отдельных каталогах `AgentArtifacts/SaveFoundationTests`; реальные данные пользователя не используются и не изменяются. Включены первый/повторный запуск, четыре состояния обучения, миграция, повреждения, checksum, backup/temp, неизвестная версия, ошибки I/O, совместимость чертежей, существующих сервисов и lifecycle hooks. Физический Android-процесс и отключение питания требуют отдельной проверки на устройстве.

`AgentScripts/VerifyJsonSaveFileStandalone.ps1` отдельно компилирует текущий файловый helper в памяти PowerShell 7 и проверяет I/O, повреждения версии/checksum, восстановление и 32 параллельные записи без Unity. Он также использует только отдельную папку AgentArtifacts.
