# Основа локализации

Используется официальный Unity Localization 1.5.13 и его Addressables. Данные находятся в `Assets/Localization`; настройки зарегистрированы в Project Settings → Localization. Стартовый и основной язык — English (`en`); все остальные языки имеют официальный fallback на `en`. Инициализация асинхронная, синхронное ожидание не включено. Выбор языка пока не сохраняется между запусками. Для Android настроена автоматическая сборка Addressables вместе с Player; локальные группы локализации включены в билд.

Поддерживаются восемь Locale Assets: English (`en`), Русский (`ru`), 简体中文 (`zh-Hans`), Deutsch (`de`), Français (`fr`), Español (`es`), Português (Brasil) (`pt-BR`), 日本語 (`ja`). Для пяти новых языков таблицы пока пустые: используется английский fallback, включая форматирование Smart Strings.

## Таблицы и ключи

Две String Table Collections вместо отдельных пустых таблиц для каждого экрана:

| Коллекция | Рекомендуемые префиксы ключей |
| --- | --- |
| `UI` | `common.`, `menu.`, `settings.`, `hangar.`, `workshop.`, `hud.`, `modes.`, `rewards.`, `progression.` |
| `Content` | `hulls.`, `weapons.`, `modules.`, `abilities.` |

В каждой коллекции есть таблицы восьми языков и прежние общие Shared Table Data. Сейчас добавлены только тестовые ключи `foundation.*`, не используемые существующим интерфейсом. `UI/foundation.items` — Smart String с аргументом `{0}`, `UI/foundation.fallback` намеренно заполнен только на английском. UI выбранного языка и его fallback предзагружается; Content загружается по запросу. Существующие GUID коллекций, таблиц и ID ключей сохранены.

Ключи должны описывать смысл и оставаться стабильными при изменении текста. В сериализуемых данных используйте официальный `LocalizedString`: ссылки по GUID коллекции и ID записи переживают переименование таблиц/ключей. Для программных запросов допустимы имена таблиц и строковые ключи.

## Доступ из игровых систем

`ILocalizationService` зарегистрирован в существующем `ProjectManagerInstaller` один раз на ProjectContext и доступен дочерним SceneContext через Zenject. Сервис создаётся по запросу. Все запросы ожидают одну общую инициализацию пакета; потребители не должны блокировать главный поток через `.Wait()` или `.Result`. Вызывать API следует из главного потока Unity.

```csharp
[Inject] private ILocalizationService localization;

// Обычная строка:
string ready = await localization.GetStringAsync("UI", "foundation.ready");

// Smart String (у записи должен быть включён Smart):
string items = await localization.GetStringAsync("UI", "foundation.items", 7);

// Для будущего экрана выбора языка:
await localization.SetLocaleAsync("pt-BR"); // Поддерживаются все восемь кодов из списка выше.
```

`InitializeAsync()` можно явно ожидать при будущем запуске локализованного экрана. `SelectedLocale` до завершения инициализации возвращает null; `IsInitialized` показывает её состояние. `LocaleChanged` передаёт официальное событие пакета после смены языка/предзагрузки. Подписчики должны отписываться при уничтожении/отключении; владелец ProjectContext освобождает сервис через Zenject `IDisposable`.

Для автоматически обновляемого текста используйте `localization.CreateString(table, key, args)` и стандартный `LocalizedString.StringChanged`, отписываясь после использования. Либо храните `[SerializeField] LocalizedString` непосредственно в будущем компоненте/ScriptableObject и используйте официальное API. Адаптер не вводит собственных форматов ссылок, таблиц, кэша или хранилища переводов.

Разовый `GetStringAsync` возвращает результат для языка, выбранного при запросе; для обновления уже показанного текста нужен `StringChanged` или повторный запрос по `LocaleChanged`. Для отсутствующего перевода используется fallback; если ключ отсутствует и там, возвращается видимый маркер `[Missing translation: Table/key]`. Ошибки загрузки таблиц/инициализации не скрываются и приводят к исключению; обработайте его на границе будущего UI. Неизвестный код языка или пустая ссылка — ошибка аргумента.

## Следующий этап

Подключать экраны постепенно через стандартные TMP localizers / `LocalizedString`, переносить реальные строки в таблицы и готовить проверенные переводы на семь дополнительных языков. Затем добавить выбор/сохранение языка и TMP-шрифты с покрытием китайского и японского текста. Для контента можно добавлять `LocalizedString` в конфиги с явной миграцией старых полей. Этот этап не меняет существующий UI, контентные конфиги или шрифты.

Одноразовые проверки находятся в `AgentScripts/VerifyLocalizationFoundation.cs`: `Run()` проверяет Edit Mode и существующий installer, `RunIsolated()` — реальный Addressables/preload в пустой Play-сцене с отдельным Zenject-контейнером, без ProjectContext и сохранений. Unity Localization 1.5.13 намеренно не предзагружает таблицы в Edit Mode, поэтому runtime preload проверяется отдельно. `LocalizationReleaseSession.Begin/Restore` подготавливает временную несохранённую сцену и восстанавливает исходную сцену, Unity Remote и playModeStartScene; Play Mode включается/выключается отдельными Pipeline-командами.

Подготовка ресурсов — `AgentScripts/SetupLocalizationFoundation.cs`; для расширения существующей основы используйте **AddReleaseLanguages()**, который не переписывает переводы и Shared Table Data и безопасен при повторном вызове. `Run()` предназначен для первоначальной подготовки основы и включает выпускные языки. Эти скрипты не входят в игровой билд и не добавляют Editor-окон или меню.
