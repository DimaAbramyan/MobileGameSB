# Отображение характеристик

В `WeaponMetaConfig` и `ShipMetaConfig` используются существующие `Base Stats Layout`
и `Secondary Stats Layout`. Новые характеристики автоматически в UI не добавляются.

1. Добавьте строку (`+ Add Row`) и ячейку (`+ Add Cell to Row`). Нажмите список
   `Manual Text` в ячейке. Для базового урона выберите `Weapon / Basic Stats / Damage`.
2. Для второго дочернего снаряда раскройте `Projectile … / Child … / Child …`, затем
   нужный контракт, например `Explosion / Explosion Radius`. Список строится по реальным
   ссылкам `Spawn Secondary Projectile`. Общий снаряд в нескольких слотах имеет отдельные
   пути; квадратные скобки содержат короткий идентификатор корневого слота.
3. В Meta корпуса выберите, например, `Ship / Ability Recovery / Recovery Settings /
   Cooldown` или `Ship / Orbit / Contact Damage`. Состав зависит от контрактов корпуса.
4. Удалите ячейку крестиком, чтобы убрать только отображение. Игровая характеристика
   останется в конфигурации. Выбор `Manual Text` возвращает сохранённые ручные Label/Value.
5. Для текущего оружия вызовите `view.Bind(weapon, weaponController)`. При повышении
   уровня `OnLevelChanged` немедленно обновляет выбранные значения: например, 20 → 25.
   Временные бонусы обновляются каждые 0,2 секунды по выбранным getter, без перестройки
   сетки и полного обхода конфигураций. Передайте реальный WeaponController для чтения
   его текущего бонуса перезарядки, в том числе до следующего выстрела.

Стрелки перемещают строки и ячейки. `Override Label` включает своё название и ключ
локализации; без него используются название и ключ дескриптора. `Value Format`
принимает, например, `0.0` или `{0:0.##} м`. Для перевода подключите
`view.SetLabelLocalizer(key => …)` к существующему сервису локализации.

`Open Layout Preview` показывает исходную Meta с выбором её уровня. `view.Show(meta)`
и `view.Preview(meta, level)` также показывают конфигурацию. `view.Bind(parentShip)`
читает текущий корпус и его существующие способности. Можно назначить живые ссылки
в Inspector компонента `StatBlocksView` или передать свой `IStatValueResolver` через
`Show(meta, resolver)`. Существующие префабы StatBox/StatRow/StatBlocksPanel сохранены;
интеграция в игровые экраны автоматически не добавляется.

В runtime значения, для которых нет итогового значения владельца, помечаются `[base]`.
Это относится, например, к зависящему от цели/пройденного расстояния урону и состоянию
ещё не созданного объекта. Такой показатель не выдаётся за итоговый урон по врагу.
Используется фактическая система улучшений игры; UI не применяет отдельно сохранённые
профили прогресса, которые само оружие сейчас не использует.

Привязка хранит ID характеристики, путь источника и ссылку на исходный asset. Переименование
asset и перестановка слотов не меняют привязку. Удалённый контракт или заменённый asset
показывает предупреждение, а не подменяется похожей характеристикой. Циклы диагностируются;
независимые пути к общему asset не объединяются. Дубли ID вложенных элементов также
диагностируются как неоднозначные и требуют исправления конфигурации.

Для нового контракта переопределите `CollectDisplayStats(StatSourceBuilder)` и объявите
его собственные значения через `Add`, вложенные источники через `Nested`. `Add` поддерживает
getter вычисляемого значения, формат, ключ локализации и явный `stableId`, сохраняемый
при будущем переименовании свойства. Адаптеры существующих контрактов находятся в
`Assets/Scripts/UI/StatContractDeclarations.cs`; чтение значений не использует Reflection.
Для модифицируемого значения способности предоставьте runtime getter через
`IStatValueResolver`, как в Orbit/Prism/Dictator/Arkanoid/Blade. Расчёт должен оставаться
общим с игровой логикой.

Функциональные проверки: `AgentScripts/VerifyStatBindings.cs` и регрессионные
`VerifyStatBlocksUI.cs`, `VerifyStatBlocksInspector.cs`. Они работают на временных
конфигурациях/preview scene и не изменяют настроенные игровые assets.

## Интеграция в NewMainMenu

Сцена `Assets/Scenes/NewMainMenu.unity` использует существующие экземпляры префаба:

- `Canvas/ScreenRoot/CraftMenu/SelectBody/HandlerTop/InfoBody/Middle/StatBlocksPanelForHull`.
- `Canvas/ScreenRoot/CraftMenu/SelectWeapon/HandlerTop/InfoWeapon/Middle/StatBlocksPanelForWeapon`.

В `HullSelectionInfoController` и `WeaponSelectionInfoController` назначено поле
`Stat Blocks View`; в соответствующих `*SelectionListController` — `Info View`.
`Middle` служит viewport с вертикальным ScrollRect; новые панели на каждый предмет
не создаются. Существующие ссылки на StatBox и StatRow сохранены.

Постоянный предмет берётся из `CraftCreationFlowController.SelectedHull`,
`FocusedWeapon` или назначенного оружия `FocusedWeaponSlotId`. `CraftUIButton`
передаёт pointer enter/exit и select/deselect. Для дочернего Button события
навигации передаёт `CraftUIButtonNavigationRelay` с назначенным владельцем в
префабах Craft/Weapon. Наведение приоритетнее навигации; после его завершения
восстанавливается навигационный фокус, затем постоянный выбор. Отключение,
уничтожение или переназначение кнопки освобождает её временный preview.

Сервис `ContentProgressService` передаётся Info-контроллеру из существующего списка
выбора (либо через Zenject). `ProgressChanged` обновляет значения на текущем уровне
Meta; строки, ячейки и кнопки списка при улучшении сохраняются. Для уровня стартовых
предметов исправлен пропуск чтения существующей записи прогресса. Улучшения и выбор
не опрашиваются через Update. Для имеющегося игрового экземпляра можно назначить
`Runtime Weapon`/`Runtime Hull` либо вызвать `SetRuntimeSource(...)`; совпадение
WeaponData/ShipData определяет использование `Bind(...)`.

Пустые layouts остаются пустыми: например, у Arkanoid на момент интеграции не заданы
ни Base Stats, ни Secondary Stats. Добавьте нужные ячейки в его Meta, чтобы увидеть
блоки; автоматического добавления всех характеристик нет.

`AgentScripts/VerifyStatBlocksScene.cs` проверяет реальные панели и EventSystem в
Play Mode, переключение нескольких предметов и обновление 20 → 25 без замены ячеек.
Проверка улучшения использует временную запись в памяти без покупки и записи Save.
