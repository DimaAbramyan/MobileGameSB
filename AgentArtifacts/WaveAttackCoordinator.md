# Wave Attack Coordinator

## Настройка

1. Выберите основной объект с `Wave`.
2. В его Inspector нажмите **Add Attack Coordinator (optional)**. Также компонент можно добавить через Add Component.
3. Добавьте группы кнопкой `+`. Раскройте группу, задайте имя и заполните `Controlled SubWaves`: выпадающий список берёт участников из расписания этой волны, включая legacy `SubWavesToCreate`.
4. Настройте завершение, задержки и повторение. Группы можно перетаскивать, копировать кнопкой **Duplicate selected group** и удалять.
5. В основном Inspector включите **Show Attack Patterns**, затем **Preview Wave Schedule**. Состояния координатора показываются в Inspector и прокручиваемой панели Scene View.

Компонент не добавляется автоматически в существующие префабы. Без компонента, при снятой галочке Enabled или выключенном компоненте атаки работают по прежним правилам.

## Завершение групп

| Режим | Условие |
| --- | --- |
| Timed | Истекло Duration после готовности и Start Delay группы. |
| Attack Cycles | Каждый живой участник выполнил Attack Cycles Count полных циклов. |
| All Completed | Каждый живой участник выполнил один полный цикл. |
| First Completed | Один живой участник выполнил один полный цикл. |

Для Single / Multiple цикл включает всех выбранных врагов, `Attacks Per Enemy Per Cycle`, Burst, Sequential Sector и перезарядку. Несколько Attack Groups внутри AttackBehaviour учитываются независимо: быстрый контроллер не заменяет завершение медленного.

Для Attack Sequence цикл — один проход последовательности, включая вложенные Repeat Blocks и авторские паузы. Координатор ограничивает число проходов в своём runtime-состоянии, поэтому бесконечная Sequence не блокирует обычный All Completed. Режим Once также может выполнить несколько проходов по явному запросу Attack Cycles. Сериализованные настройки Sequence не меняются.

Уже выпущенные снаряды и их дочерние атаки продолжают жить. Обычная длительность жизни снарядов не участвует в завершении. Явное ожидание Child Attack в Sequence сохраняется; Max Wait Duration ограничивает ожидание на уровне группы.

`Wait Until Ready` ожидает появления всех врагов и начала post timeline после входного маршрута. Если флаг выключен, группа открывает разрешение сразу: доступные entrance-атаки могут стрелять, а post-атаки начинают работу при достижении своей штатной фазы. Циклы post-атак до этой фазы завершиться не могут.

Погибшие слоты пропускает существующий AttackBehaviour. Когда подволна полностью теряет врагов, `On Enemy Death` позволяет исключить её из ожидания либо завершить группу. Удалённые ссылки не блокируют группу; Inspector показывает предупреждение о сломанной конфигурации.

## Переключение и перекрытие

- **Finish Current Attack:** закрыть запуск новых атак, дать текущим Burst / Sector завершиться. Движение продолжается.
- **Interrupt:** приостановить дальнейшие выстрелы и отложенные запуски. Выпущенные снаряды сохраняются.
- **Restart:** при следующем включении перезапустить runtime-цикл с его штатными начальными задержками.
- **Resume:** сохранить курсоры, текущую очередь и оставшуюся перезарядку; время ожидания не превращается в накопившийся залп.

У Timed следующая группа может начаться в момент `Start + Duration + Delay After Group + Global Cooldown − Overlap Duration`, не раньше начала текущей группы. Сама текущая группа прекращает разрешать новые атаки по окончании Duration. При Finish Current Attack оставшиеся выстрелы могут завершаться параллельно следующей группе; Overlap Duration ограничивает это завершение.

Для условий по фактическому завершению момент окончания заранее неизвестен. Следующая группа запускается после выполнения условия и задержек; Overlap Duration разрешает параллельное завершение исходящей атаки, если оно ещё требуется. Закончившиеся атаки повторно ради перекрытия не запускаются.

Если подволна входит сразу в несколько активных групп, используется одно разрешение и максимальный требуемый бюджет циклов. Переход одной группы в ожидание не выключает подволны, нужные другой группе, и не перезапускает их атаку.

`Max Wait Duration` по умолчанию 30 секунд, включает Start Delay и ожидание готовности. Ноль отключает таймаут. Inspector предупреждает о возможном бесконечном ожидании и о таймауте короче заданной длительности. Нулевые циклические группы имеют ограниченный объём работы за кадр.

`Loop Sequence` — бесконечное повторение; при выключении используется конечный Loop Count. Start Group Index начинается с нуля. Random Seed зарезервирован для случайного порядка координатора: текущий порядок групп последовательный, а собственные Seed паттернов не переопределяются.

После конечной последовательности участники остаются в ожидании. `Stop Coordinator`, выключение компонента или галочки Enabled освобождает управление; `Restart Coordinator` запускает его заново. Завершение / уничтожение волны освобождает все запросы.

## Интеграция с другими блокировками

`DirectedWaveAttackBehaviour.SetExternalAttackPermission(owner, permission)` принимает запрос конкретного владельца:

```csharp
attack.SetExternalAttackPermission(this, WaveAttackPermission.BlockNewAttacks);
// ...
attack.ReleaseExternalAttackPermission(this);
```

Доступны AllowAttack, BlockNewAttacks и InterruptAttacks. Действует наиболее строгое ограничение всех владельцев. Освобождение одного запроса не снимает чужую блокировку. Владелец обязан освобождать свой запрос при завершении / отключении.

Ссылки содержат номер записи расписания и ожидаемый prefab. Одинаковый prefab в нескольких записях можно выбирать независимо. После изменения порядка самого Conductor Schedule следует перепроверить / перевыбрать участников: несовпавшая ссылка предупреждается и не перенаправляет управление на другой prefab автоматически.

## Основные файлы

- `Assets/Scripts/Gameplay/Waves/WaveAttackCoordinator.cs` — компонент и настройки.
- `WaveAttackCoordinatorPlayer.cs` — общий для Runtime и Preview порядок групп и владение разрешениями.
- `WaveAttackPermissions.cs` — объединение запросов разных систем.
- `DirectedWaveAttackBehaviourPermissions.cs` — адаптация существующих контроллеров и учёт циклов.
- `Assets/Editor/WaveAttackCoordinatorEditor.cs` — Inspector и выбор участников.
- `WaveConductorPreviewCoordinator.cs`, `WaveShootingPreviewCoordinator.cs` — отображение и адаптация Preview.

## Проверка

Проверочные скрипты находятся в `AgentScripts/VerifyWaveAttackCoordinator*.cs`, результаты — в `AgentArtifacts/coordinator-*.json`.
Проверены группы, перекрытие, общие участники, смерть, таймаут, сохранение Burst / Sector / cooldown, ограничение Sequence, отдельные Attack Groups, настоящий ECS Preview, Undo/Redo, Prefab Overrides, копирование и перестановка, повторный старт / очистка Preview. Дополнительно выполняются регрессии существующих атак и сравнение семи разрешённых волн с предыдущими снимками.

Полный ручной бой на устройстве не проверялся. Unity Test Runner не обнаруживает NUnit-тестов; функциональные проверки выполняются через Pipeline в уже открытом Editor.
