# Рандомизация числовых параметров волн

Поддерживаемые поля получили кнопку **⚄** справа. Выключено — исходное число; включено — **Min / Max**. При первом включении оба предела берутся из текущего фиксированного значения. После этого фиксированное число и диапазон хранятся независимо: переключение не стирает ни одно из них.

Исходные float-поля и их сериализованные имена сохранены. Рядом добавлены выключенные по умолчанию диапазоны; миграция и пересохранение префабов не требуются. Значения Min > Max допускаются: выбор выполняется между меньшим и большим пределами без перестановки сохранённых данных. Min = Max даёт постоянное значение. Для скорости нижняя граница 0.01, для кулдауна — 0; Offset допускает отрицательные значения.

## Emission Origin

`Attack Pattern → Shooting Behaviour → Emission Origin → X / Y Axis → Offset`.

- Кубик включается независимо для X и Y.
- **Randomize On** выбирает момент нового значения: On Attack Start / On Burst Start / On Shot (весь залп).
- **Capture Mode** Player остаётся отдельной настройкой захвата координаты игрока. Она не заменяется рандомизацией Offset.
- Enemy/Player: выбранный Offset прибавляется к соответствующей координате.
- World Absolute: Min/Max являются абсолютными мировыми координатами.
- World Boundary: выбранный Offset применяется к текущей границе игровой области; положительный — внутрь, отрицательный — наружу.
- Sequential Sector хранит исходную точку и числовые значения своего залпа до завершения всех отложенных направлений. Следующий залп не может изменить уже запланированный.

Без Burst режим On Burst Start выбирает значение для одной полной атаки. X и Y могут использовать разные частоты выбора.

## Attack Cooldown

Кубик доступен у `Attack Timing → Attack Cooldown` в Single/Multiple-паттернах, а также у `Override Enemy Attack Cooldown → Enemy Attack Cooldown` в AttackBehaviour.

Значение выбирается один раз при назначении кулдауна. Проверки готовности и чтение свойств не генерируют новые числа. Сохраняются источники Enemy Settings / Wave Override, Attack Presets, Local Overrides и множитель Attack Sequence. Для полного Multiple-цикла берётся максимум кулдаунов его паттернов; общий override сохраняет свой прежний приоритет.

При рандомизированном кулдауне Inspector показывает диапазон длительности полного цикла.

## Projectile Base Speed

Кубик доступен:

- `Projectile Settings → Override Projectile Base Speed → Projectile Base Speed`;
- у Stack Initial Speed, когда он служит источником базовой скорости;
- `AttackBehaviour / группа / шаг Sequence → Override Base Projectile Speed → Base Projectile Speed`;
- у соответствующего поля Attack Preset.

При включённом диапазоне появляется **Randomize On**:

| Режим | Выбор значения |
|---|---|
| Per Attack | Одно на полную атаку |
| Per Burst | Одно на каждую очередь; без Burst — одно на атаку |
| Per Shot | Одно на залп, включая все его Fan/Stack/Emission-направления |
| Per Projectile | Отдельно для каждого снаряда |

Отложенные Sector используют сохранённый снимок скорости своего залпа. Per Projectile определяется индексом снаряда, поэтому задержка запуска и выборочная отрисовка Preview не меняют его результат.

Приоритеты прежние: явное локальное переопределение → применимый общий runtime override → базовая скорость паттерна/Stack → prefab. `Initial Speed Mode = Random` по-прежнему использует собственные Min/Max выше Base Speed. Для него добавлен **Seeded Initial Speed Random**: выключено по умолчанию и сохраняет прежний алгоритм, включая совместную скорость DNA fan; включено — использует общий Seed и выбранный Randomize On. Таким образом существующие Random-паттерны не меняют поведение автоматически.

В Consistent случайное базовое значение сочетается с накопленным изменением скорости после каждого полного залпа. Скорость полёта и её последующие кривые/движение продолжают работать через существующие системы.

## Seed и Preview

**Numeric Random Seed** находится в Projectile Settings каждого паттерна, по умолчанию 12345. Потоки зависят от Seed, стабильного ID слота и номера атаки, а не от Unity instance ID. X, Y, скорость и кулдаун имеют отдельные потоки. Новая система не расходует глобальный Unity Random.

В общих Shooting Preview Controls:

- **Preview Seed Offset = 0** — использовать авторские Runtime seeds;
- **Repeat Seed** — пересоздать симуляцию с теми же значениями;
- **New Seed** — выбрать новый временный Seed Offset и пересчитать Preview;
- **Runtime Seed** — вернуть Offset = 0.

Offset прибавляется к Numeric Random Seed, не изменяя префабы/пресеты. Он общий для Preview и хранится только в текущей сессии Editor. Для переноса выбранного варианта в Runtime прибавьте этот Offset к seed нужного паттерна и верните Preview Offset к нулю.

Анимированные Preview Wave / In Formation / Wave Schedule исполняют те же события выборки. Статические Scene guides показывают первый образец новой атаки. Дочерние атаки используют общий построитель снарядов и наследуют воспроизводимый ключ от родителя; их Emission Origin по-прежнему задаётся родительским снарядом. Сохраняется прежнее ограничение Preview на полноценную симуляцию зависимых от игрока пикирования.

## Расширение на другие поля

Общие типы: `RandomFloatRange`, `RandomIntRange`, `NumericRandomStream`, атрибут `Randomizable` и `RandomizableNumberDrawer`.

Пример с сохранением уже сериализованного поля:

```csharp
[SerializeField, Randomizable(nameof(speedRandom), .01f)] private float speed = 1f;
[SerializeField, HideInInspector] private RandomFloatRange speedRandom = new();
```

В обработчике нужного события вызывайте `speedRandom.Sample(speed, ref stream, .01f)` и сохраняйте результат. Не вызывайте Sample в getter или Update для уже выбранного значения. Int использует включительные Min/Max и равномерную выборку без смещения округления.
