# Attack Order

В `DirectedWaveAttackBehaviour` откройте настройки нужной группы/Attack Pattern → **Scheduling → Use Attack Order**. У шагов Attack Sequence блок находится внутри Attack Pattern шага. Для назначенного Attack Preset порядок редактируется в самом пресете.

По умолчанию функция выключена. Старые Scheduling, Single/Multiple, Local Overrides и Spawn Order сохраняются. Включение Attack Order переключает выбор атакующих на новый порядок; старые `Attacks Per Second`, `Wait For Previous Attack` и `Delay After Attack` становятся неактивными. `Attacks Per Enemy Per Cycle`, паттерны, Burst, кулдауны и движение продолжают исполняться существующим контроллером.

## Режимы

| Режим | Порядок |
|---|---|
| Simultaneous | Все выбранные враги в одной пачке; Enemies Per Batch не используется |
| Sequential | По ID слота; с Spatial Order — слева направо, при равном X сверху вниз |
| Random | Детерминированное перемешивание по собственному Seed, независимо от Unity Random и Spawn Order |
| Center To Outside / Outside To Center | По расстоянию до центра выбранной группы |
| Left To Right / Right To Left | По X, при равном X — по Y |
| Clockwise / Counter Clockwise | По углу вокруг центра группы, начиная сверху |
| PingPong | Проход вперёд и обратно без повторения крайних слотов: 0, 1, 2, 3, 2, 1; затем новый проход |
| Symmetrical Pairs | Зеркальные пары относительно вертикальной оси через центр группы, снаружи внутрь. Подбирается ближайший к зеркальной позиции враг на противоположной стороне; центральные/непарные слоты остаются отдельными |
| Manual | ID слотов в заданном списке. Неперечисленные слоты не атакуют. Повторяющиеся ID разрешены |

При одинаковых геометрических ключах используется ID слота — порядок не зависит от порядка перечисления живых врагов или появления. Центр — среднее позиций выбранной группы на момент снимка.

## Настройки

- **Attack Interval Between Enemies** — интервал между запусками пачек, по умолчанию 0.15 с. Время учитывает существующие модификаторы скорострельности; множитель шага Sequence также масштабирует интервал.
- **Enemies Per Batch** — число врагов, запускаемых вместе, по умолчанию 1. В Symmetrical Pairs пары не разрываются: минимум 2, нечётный размер округляется вниз до чётного. Несколько пар можно запустить одной пачкой.
- **Start Slot** — ID слота, с которого начинается вычисленный порядок. −1 (по умолчанию) означает первый элемент выбранного режима. Для пар выбирается целая пара. Отсутствующий ID не меняет начало.
- **Reverse Order** — обратный порядок; у Symmetrical Pairs разворачиваются целые пары.
- **Loop Order** — повторять циклы. Выключено — выполнить один цикл. По умолчанию включено.
- **Random Seed** — seed отдельного генератора, по умолчанию 12345.
- **Order Source → Formation Slot Order** — стабильные ID для Sequential/Random/Manual и исходные координаты формации для геометрических режимов. **Spatial Order** — фактические мировые позиции на начало цикла. Spawn Order не используется.
- **Wait For Previous Enemy** — дождаться всех участников предыдущей пачки: Burst, отложенного Sequential Sector, движения/возврата и Attack Cooldown. Участники одной пачки могут атаковать одновременно. По умолчанию выключено. Интервал между стартами остаётся нижней границей, а не дополнительной задержкой после кулдауна.
- **Reset Order Each Cycle** — обновлять снимок геометрии и сбрасывать Seed на каждом цикле. По умолчанию включено. Выключено — сохранить первый снимок и продолжать случайную последовательность генератора. Новый запуск контроллера/шага Sequence начинает собственный порядок.
- **Manual Slots** — список реальных ID слотов, а не номеров появления. Пустой список отмечается предупреждением и не запускает атаки.

`Attacks Per Enemy Per Cycle` задаёт число проходов выбранного порядка внутри цикла. Для PingPong внутренние слоты встречаются и на прямом, и на обратном пути. В Sequence одно повторение шага всегда выполняет один конечный цикл независимо от Loop Order, чтобы последовательность могла перейти дальше.

## Очередь, уничтожение и конфликты

Уничтоженный или недоступный враг пропускается без перестройки оставшейся очереди и без отдельного интервала для пустой пачки. Если следующий живой враг ещё исполняет Burst/движение или находится на кулдауне, он сохраняет место в очереди: более поздние враги его не обгоняют.

Уникальные ограничения движения сохраняются. Например, при Dive Scheduling → Wait For Return несколько пикирующих врагов не начнут движение одновременно даже в одной пачке; для параллельных пикирования настройте существующий Dive Scheduling.

Ожидание Child Attack регулируется прежними настройками шага Attack Sequence; полёт обычных снарядов не задерживает Attack Order.

## Scene View и Preview

При выборе AttackBehaviour Scene View показывает запланированный порядок: номер атаки, номер пачки, ID слота и соединяющую линию. Анимированные Preview Wave / In Formation / Wave Schedule используют тот же построитель порядка и показывают следующую позицию очереди жёлтым. Static guides показывают первый проход на исходной формации; Spatial Order в анимированном Preview использует текущую позицию врагов. Изменения Inspector/пресетов перезапускают Preview существующим механизмом.

Остаётся прежнее ограничение Preview: зависимые от игрока пикирования полностью не симулируются.

## Реализация и проверка

- `DirectedWaveAttackOrder.cs` — сериализуемые настройки и общий построитель порядка без собственного таймера стрельбы.
- `DirectedWaveAttackControllerOrder.cs` — выбор пачки внутри существующего Runtime-контроллера; используются его часы, корутины атак и кулдауны.
- `WaveShootingPreviewOrder.cs` — порядок в существующей симуляции Preview.
- `DirectedWaveAttackOrderSettingsDrawer.cs` — Inspector и Scene guides.

Проверены 52 новых сценария механики, реальная отрисовка Inspector и Scene/animated guides, Undo/Redo, вложенная сериализация, Prefab Overrides и очистка/перезапуск Preview без утечек ECS-миров. Пройдены регрессии Sequence, Burst/Sector, Child Attack, Local Overrides, Multiple и Wave Schedule — всего 11 проверочных наборов.

Все 7 разрешённых Extreme-волн совпали с исходным снимком: хеши префабов, 29 subwaves, 259 слотов, 3515 образцов позиции и прежние значения настроек атак. При сравнении исключено только новое поле `attackOrder`, предварительно проверенное как выключенное. Префабы не пересохранялись.

Unity recompile/domain reload завершились, новых ошибок Console нет. Обе обязательные сборки `dotnet build --no-restore --verbosity:quiet --nologo` успешны: Runtime — 0 ошибок и 115 существующих предупреждений; Editor — 0 ошибок и предупреждений. Индекс codebase-memory обновлён.

Логи находятся в `AgentArtifacts/order-*.json` и `order-*-build.log`. Полный бой в Play Mode и мобильное устройство не проверялись.
