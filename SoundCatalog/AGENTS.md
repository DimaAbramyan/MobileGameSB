# Подбор звуков для игры

Перед добавлением звуков прочитать `README.md`. Эти правила действуют для последующих запросов пользователя.

- Искать только конкретный объект или механику, указанную пользователем. Не начинать массовый поиск для всей игры и не повторять старый поиск лишь из-за изменения правил.
- Цель каждого поиска — 20–30 различных качественных готовых эффектов из нескольких бесплатных библиотек. Различаться должны характер и фактура, а не только высота, уровень или номер дубля. Вариации одного эффекта и демонстрации повторения не считать отдельными кандидатами.
- Качество важнее количества: при 17 подходящих записях оставить 17 и сообщить о результате. Не добавлять слабые звуки, примитивный синтез или производные одного семпла для заполнения количества.
- Приоритет — профессионально звучащие готовые записи, в том числе из смежных категорий. Избегать примитивных электронных писков, резкого верха, чрезмерных атак и навязчивых резонансов. Учитывать многократное повторение и множество источников в bullet hell.
- Предпочитать CC0; другие лицензии принимать только с проверенными коммерческими правами и понятной атрибуцией. Хранить автора, первоисточник, ссылку скачивания и доказательства лицензии каждого материала.
- Хранить неизменённые оригиналы отдельно от превью и обработанных файлов. Для сравнения выравнивать воспринимаемую громкость превью внутри одной подборки; фиксировать метод, усиление и измерения, проверять пики. Одного совпадения пиков недостаточно. Для коротких часто повторяемых эффектов измерять сопоставимые последовательности; внутри кандидата сохранять общее усиление для разных темпов.
- Отмечать пять наиболее перспективных кандидатов (либо все, если найдено меньше пяти) полем `shortlist: { rank: 1..5, reason: "..." }`. Объяснять пригодность и ограничения. Это предварительная рекомендация; не менять пользовательское избранное и не выбирать финальный звук.
- Не объявлять техническое декодирование/автотест прослушиванием на слух. Если оценка комфорта на слух недоступна, прямо указывать пределы оценки.
- Дополнять существующий каталог, сохранять прежние записи, ID, избранное и заметки. Не перезапускать старые генераторы для замены результатов без отдельной задачи.
- Перед каждым новым поиском прочитать весь `dist/Removed/index.json` (включая сохранённые источники, ID и метаданные). Это постоянный список отклонённых звуков: не предлагать их снова и не восстанавливать автоматически. Сначала также учитывать активные записи `dist/catalog.js`.
- До копирования кандидата в активную аудиотеку использовать `audio_identity.ImportGate` / CLI `python audio_identity.py FILE ...`. Проверять ID и URL источника (для ZIP обязательно конкретный archiveMember), названия/автора, SHA-256 и аудиосодержимое против активных и Removed. Одно название или похожий тембр не являются доказательством дубликата. Исследовательские оригиналы могут оставаться в `.local/research`, но отклонённые записи не должны попадать в активный индекс.
- Все импортёры обязаны сохранять новые записи только через `CatalogStore.import_records()` из `catalog_store.py`. Прямая перезапись `dist/catalog.js` импортёром запрещена: она обходит проверку Removed и блокировку параллельных изменений. Проверка выполняется ещё раз под общей блокировкой перед фиксацией. Восстановление из Removed допустимо только по явному действию пользователя через кнопку ↶ или API restore; обычный импорт ничего не восстанавливает.
- Не чистить `dist/Removed/`, его `index.json`, журнал `data/catalog-transaction.json` или пользовательские отметки. Переносы и восстановление выполнять через `CatalogStore`, чтобы сохранить файлы и возможность восстановления после сбоя. Если журнал остался после сбоя, позволить Store завершить восстановление, а не удалять журнал вручную.
- После поиска обновить каталог, проверить реальные аудиофайлы, самостоятельно открыть его в браузере. Unity/FMOD не изменять без разрешения.
- По просьбе пользователя после использования Computer Use завершать использованный сеанс и служебные процессы `codex-computer-use.exe` и его аналоги из runtime Codex, затем проверять результат, чтобы не оставалась жёлтая обводка. Браузер и сервер каталога оставлять работающими. Если помощник автоматически перезапускается самим ChatGPT, не закрывать ChatGPT и не создавать бесконечный цикл завершения: явно сообщить об этом ограничении.
