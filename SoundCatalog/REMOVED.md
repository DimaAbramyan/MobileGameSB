# Removed: отклонённые звуки и защита импорта

В карточке любого активного трека есть компактная корзина. Один клик немедленно скрывает карточку и останавливает её обычный или автоматический плеер; подтверждений нет. На сервере выполняется перенос. Ошибка возвращает карточку и выводит причину. Быстрые повторные нажатия не создают повторных операций.

Раздел **Removed** в левой колонке показывает только отклонённые записи. В нём доступны локальный плеер, оригиналы, вариации и очереди, источники, лицензии, дата удаления, исходный путь, заметки и звёздочка. Кнопка ↶ возвращает запись в прежнюю категорию одним нажатием. После восстановления её ID исключается из списка отклонённых. Как активная запись она по-прежнему защищена от дублирования новым импортом.

## Хранение и сбои

- `dist/catalog.js` содержит только активные треки. Категории и объекты сохраняются, даже если временно опустели.
- `dist/Removed/index.json` — постоянный индекс: полная исходная запись, категория, объект, UTC-время, исходная позиция в списке, соответствие всех прежних и архивных путей, SHA-256 каждого перенесённого файла.
- `dist/Removed/<stable-id>/files/` — реальные файлы с сохранением дерева прежних путей: оригиналы, превью, вариации, очереди, журналы их событий, лицензии и сведения об обработке. Разные ID и полные пути исключают конфликт одноимённых `source.wav`.
- Исходники, используемые другими активными треками, и общие рецепты сохраняются для них; в архив создаётся отдельная копия. Восстановление не перезаписывает посторонний файл. Уже существующий общий файл принимается только при совпадении SHA-256. После восстановления могут оставаться резервные общие копии внутри прежней папки; без записи в `index.json` они не считаются отклонённым треком и не блокируют импорт.
- `data/catalog.lock` синхронизирует сервер, несколько вкладок и CLI-импорт на Windows/Linux. `data/catalog-transaction.json` — журнал незавершённого переноса. Файлы проверяются до начала операции, новые индексы пишутся через временный файл + fsync + atomic replace. Незавершённая операция откатывается при следующем обращении/запуске; журнал нельзя удалять вручную.
- `data/selections.json`, стабильные ID и browser storage не меняют формат. Удаление не стирает отметки; восстановление возвращает прежнее избранное и заметки.

Архив не публикуется в интернет: его отдаёт тот же сервер только на `127.0.0.1`. Лицензии записей продолжают действовать и после их отклонения.

## Обязательная проверка импорта

`catalog_store.py` — единственное место записи активного каталога. `CatalogStore.import_records()` заново читает весь Removed под общей блокировкой и проверяет кандидатов против архива, активных треков и уже принятых записей того же пакета. Все три импортёра подборок и рецепт `design_machine_gun_v2.py` подключены к этому механизму. Известные активные и отклонённые ID пропускаются до создания файлов; повторный запуск не регенерирует их.

`audio_identity.py` проверяет:

1. Стабильный ID, Freesound Sound ID, явные ID источника, URL конкретного аудиофайла, а для архивов — **URL ZIP + конкретный archiveMember**. Общая страница Sonniss или один ZIP сами по себе не блокируют все записи набора. Общий записанный слой не делает разные готовые дизайны одинаковыми.
2. Название и автора как дополнительную подсказку, а не самостоятельный запрет.
3. SHA-256 реальных байтов кандидата против оригиналов, основного файла и вариаций существующих записей.
4. Аудиосодержимое: mono PCM 8 kHz с удалением DC/низкого гула, нормированная взаимная корреляция волны с поиском временного смещения и проверкой четырёх независимых участков. Совпадение требует общей корреляции ≥0,985 и ≥0,975 в минимум трёх информативных участках. Спектральное сходство или принадлежность одному жанру не используются как причина отклонения.

Сравнение обнаруживает идентичные lossless-записи, WAV/FLAC/MP3-перекодирование, другую частоту дискретизации, имя и усиление, включая инверсию фазы. Это консервативный анализ содержимого, а не обещание обнаружить любое производное: произвольные короткие вырезки, заметное изменение высоты/темпа, сильный монтаж и очень низкокачественное кодирование не гарантируются. Сравниваются записи с отношением длительностей не менее 0,85; для необычно длинных файлов анализируются первые 600 секунд, полный SHA-256 остаётся обязательным.

Кэш PCM по SHA-256: `data/audio-fingerprints/`. Для **импорта и анализа** нужны NumPy и ffmpeg, уже используемые инструментами подбора. Сервер и прослушивание остаются на Python standard library и браузере; корзина не запускает тяжёлый аудиоанализ. При невозможности анализа импорт прерывается, а не добавляет непроверенный файл молча.

Пример предварительной проверки (код возврата 2 означает найденный дубликат):

```powershell
cd "C:\My project\SoundCatalog"
python -X utf8 audio_identity.py "C:\path\candidate.wav" --id candidate-id --source-url "https://example.com/sounds/123" --download-url "https://example.com/123.wav" --title "Candidate"
```

В Python: `ImportGate.allow(id, source_path, metadata)` перед созданием активных файлов, затем `gate.store.import_records(records, categories, objects)`. Исследовательские загрузки могут храниться в `.local/research`; попадание в активный индекс проходит обязательный admission gate. Смена названия, ID или сайта не обходит проверку байтов/PCM. Обычный импорт никогда не вызывает restore.

## Проверки

```powershell
python -X utf8 tools/test_removed.py
node tools/test_archive_ui.mjs
node tools/test_automatic_fire.mjs
node --check dist/app.js
node validate.mjs
```

Изолированные тесты создают только собственные небольшие аудиофикстуры в `.local/tests/removed/`: перенос/восстановление обеих категорий, перезапуск HTTP, Range-воспроизведение архива, повторные запросы, ошибки, аварийное восстановление индексов, конфликты назначения, общие источники, отказ импорта по ID/URL/SHA/PCM и разрешение другой похожей записи. JS-тест запускает реальный обработчик UI с отложенными HTTP-ответами: мгновенное скрытие, остановка, двойной клик, возврат при ошибке, последовательная фиксация.

Явная браузерная диагностика `?object=flamethrower-arcade&check=archive` нажимает корзину первого видимого трека, проверяет немедленное исчезновение и остановку, открывает Removed, проверяет воспроизведение и восстанавливает запись в `finally`. Обычные URL этот тест не запускают. Результат доступен через `/api/playback-check`. Он не заменяет субъективное прослушивание.

- 13 изолированных Python-тестов прошли, включая имитацию блокировки файла, заполнения диска при копировании/записи индекса и аварийного завершения между записями двух индексов.
- JS-проверки корзины и существующего автоматического плеера прошли; синтаксис app.js и Python-модулей корректен.
- В реальном Zen Browser: **9/9** проверок Flamethrower и **9/9** проверок Minigun v2, в том числе начало воспроизведения архивной версии. Это функциональные проверки, не оценка звука на слух.
- После тестовых переносов восстановлены все **82** записи; метаданные, категории, порядок и пользовательские отметки совпадают с исходными. Проверены локальные ссылки и SHA-256 через существующий validate.mjs.
- Повторный запуск всех четырёх импортёров/рецептов пропустил известные записи без регенерации аудио. Проверка отклонённых ID, других имён, URL, lossless-перекодирования с изменением уровня/частоты дискретизации, MP3 и похожей другой записи воспроизводится в test_removed.py.
- Сервер версии 2 работает на прежнем адресе 127.0.0.1:8765; формат сохранения избранного прежний. Структура Removed создана, тесты не оставили отклонённых реальных треков.
- Локальные отчёты: `.local/research/removed-feature/{verification,browser-flamethrower,browser-minigun}.json`; изолированные тестовые данные находятся в `.local/tests/removed/`.
